# 0022 — 没有协议面：不做 MCP、不做 A2A、不读 skill 文件

> **语言：** [English](0022-no-protocol-surface.md)（主文档） · [中文](0022-no-protocol-surface.zh-CN.md)

**状态：** Accepted（2026-10-28）。一条常设的拒绝；它不新增面，也不新增门。
**日期：** 2026-10-28

## 背景

ADR-0001 定了 k10r 的面：会话控制、记忆、任务，并把 memory-primary 说成一种消费姿态而非第四个面。它没有定的是 k10r **拒绝成为什么**：2026 年记忆/技能服务的行业形态是 MCP server（把工具经 JSON-RPC 暴露给任何愿意接的客户端），或者一个让对端注册进来的 agent 间端点；技能则习惯上是目录里的一堆 `SKILL.md`，由宿主扫描并注入。

这些形态都在回答一个问题，而这个问题这套系统没有：**陌生实现之间的互操作**。协议在对端是外来者时才划算——不同厂商、不同运行时、运维装的是别的东西。文件式技能目录也一样：它在能力清单有界、归属是一个人、边界靠手工划定时划算——几十个技能、一个宿主、一个维护者。

目标形态两条都不占。k10r 的消费方是同一套栈产出的同构 agent 循环；它服务的组织是液态的：编组按目标成立、任务结束即解散，能力边界随使用漂移，权限是拓扑而不是逐个对象的授权。在这个形态里，协议带来的动态信任面（谁都能注册、什么都能热插拔）是负担，而文件的固定边界是一个和所盛之物不再匹配的容器。

## 裁决

**RULING — k10r 只暴露 ADR-0001 的三个面，到三为止。不实现 MCP server，不实现 A2A 类端点，也不实现 skill 文件加载器。**

1. **门就是接口。** `/channels`、`/memories`、`/skills`、`/tasks`、`/code`、`/graph`（SEAM.md §1）是消费方调用的东西，走一种传输（mem-server 的 HTTP；同机时内存内链 mem-core 是实现细节，见修订后的 ADR-0007）。外部客户端想用 k10r，就为这些门写适配器；k10r 不为了迎它长出第二张面。

2. **不做 MCP server。** k10r 不提供的工具不能被广告：工具面是 gravity 那份固定、硬编码的列表（gravity ADR-0004），其中每一条都是 k10r 的一扇门。把这些门裹进 JSON-RPC，等于为这个部署里并不存在的对端，每条连接加一条通道（身份、能力声明、schema 版本、超时、重试、投递语义、幂等），再加一个注册表来说明哪些工具是活的——在一个以「只追加、无策略的真相」为全部设计的基底上，加一张动态面。

3. **不做 A2A 类端点。** k10r 不是 agent，也不寻址 agent。技能执行走 gravity 的那条链（`resolve_skills` → `invoke_skill` → 节点 mount），从不经过注册表里发现的对端。agent 之间的协调是 k10r 已经持有的状态：事实与任务顶点（ADR-0021）。在这里加一条 agent 间通道，等于把那份状态复制成消息，并在图旁边再开一个故障面。

4. **技能是节点，不是文件**（ADR-0015）。`POST /skills/{scope}` 是声明门，resolve 按意图给候选，步骤的代码是一行 code row（ADR-0012）。不扫描目录、不注入 `SKILL.md`、也没有靠手工划定的边界——边界是随使用漂移的子图。文件是那个子图在某一时刻的一次导出，所以项目自己的工具仍然可以渲染一份，只是 k10r 不会把它读回去。

5. **这条拒绝是同一根判据用了三次。** 生态轴度量陌生实现之间的握手成本，扩展轴度量随实体数量增长的成本与损耗。在这个部署里，k10r 在第一根轴上的收益是零，在第二根轴上压力最大——两根轴指向同一处，所以答案是结构性的，不是口味。

## 已考虑并否决

- **在门的正面挂一个 MCP server。** 它服务的是这套栈没有的客户端，并且把能力清单变成运行时注册表——这恰好是一个从不改写真相的基底绝不能持有的东西。
- **开一个 A2A 端点，好让别的框架的 agent 来问 k10r 一句话。** 同一个问题是门调用，同一个答案是投影。协议新增的是每个操作的第二个名字，以及一条要维持活着的通道。
- **skill 目录加载器（扫 `SKILL.md` + frontmatter 建索引）。** 它假设数量有界、边界由人划定。一旦数量越过几十、技能开始随使用合并与分裂，这两条都不成立；加载器此后维护的是一份与它所依据的图相互矛盾的快照。
- **一个接受运行时注册的插件/工具注册表。** 注册是「谁注册谁对能力边界做一次写」——与「写入限于调用方 scope 内的事实追加」正好相反。

## 后果

- **适配的责任在调用方，不在核心。** 未来任何外部消费方都照 SEAM.md 的门写适配器。这是正确的工作方向：适配器懂自己的方言，k10r 只有一套词汇。
- **没有动态信任面。** k10r 能提供什么，由它的门与 schema 固定，不由谁注册过决定——审计线索是追加日志，不是某张注册表的配置历史。
- **三张面必须够用。** 若某个消费方需要三个面答不了的东西，答案是新增一扇门或改投影，并以 ADR 评审——不是往旁边栓一个协议。
- **代价落在分发上，这是故意的：** 文件目录可以复制、协议可以安装，而 k10r 的形态必须经它的门才能到达。这份代价每个部署付一次，不随 agent 数量重复支付——这正是液态组织想要的交换。
