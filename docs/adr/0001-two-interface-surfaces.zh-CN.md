# ADR-0001: 双接口面 — 会话控制与记忆

**状态**：Accepted（设计定案，实现未开始）
**日期**：2026-09-08
**英文版**：[0001-two-interface-surfaces.md](0001-two-interface-surfaces.md)

## 背景

skillforge 旧 mem 模块把两件因不同原因而变化的事情混在一起：

1. **会话管线** — 消息追加、prefix checkpoint、压缩触发。自动触发逻辑埋在
   `ConversationMemory.__init__`（`checkpoint_threshold`）：阈值判断和尾提示词
   注入硬接线在 `get_context()` 里。
2. **记忆检索** — flat 长期记忆 + 混合检索，作为辅助上下文注入。

自动触发是**策略**，不是**机制**。策略埋进存储层意味着调用方无法关闭它、
无法按 session 改阈值、无法在其他时机触发压缩（比如一个工作单元结束时，
而不是消息计数到达时）。

## 决策

核心只暴露两个接口面。

### 接口面 1：会话控制（完全控制模式）

三个可组合的原语，由 agent 显式驱动：

```
branch(fork_point)    从任意前缀点分叉会话。checkpoint 不可变（前缀模型），
                      分叉零拷贝：分支共享 checkpoint 前缀，增量消息各走各的。

tail(prompt)          单回合分支。fork → 末尾注入指令 → turn 执行 → 分支丢弃。
                      主会话历史无痕（历史上的"历史纯净性"保证，现在成为
                      结构性质）。

summarize(...)        组合操作：注入压缩指令（经 tail）→ 回收摘要 → 截断
                      已压缩消息 → 写入新 checkpoint。会话收缩。
```

尾提示词注入和总结都是分支操作：尾提示词 = 只有一个回合的分支；
总结 = 注入 + 截断。一个机制，没有特例。

**触发策略移到调用方。** 核心只提供原语；*何时*总结（阈值、会话结束、
显式命令）是 agent 侧策略。旧自动触发降格为调用方可选策略之一，
不再是核心行为。

### 接口面 2：记忆（辅助模式）

两种模式：

- **完整会话模式** — `get_context` 返回完整上下文（checkpoint 摘要 +
  DB 增量 + pending 用户消息）。会话本身即记忆，检索不参与。
- **常规辅助模式** — flat 记忆与图事实的 `store` / `search` / `forget`。
  检索结果是**辅助性**的：随会话注入，永不替代会话。

## 后果

- 存储核心从不决定*什么时候*，只决定*怎么做*。mem-core 因此不含策略、
  极易测试。
- 旧的 `checkpoint_threshold` 构造参数和 `get_context()` 内的尾提示词分支
  消失；调用方显式组合 `tail()` / `summarize()`。
- 分支要求 checkpoint 前缀模型严格保持（checkpoint 不可变、消息按创建
  顺序全序）。这是存储 schema（ADR-0002）必须遵守的约束。
- "历史纯净性"（尾提示词永不落盘）从"靠小心代码维持的约定"变成
  "单回合分支的结构性质"。
