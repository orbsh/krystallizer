# 0012 — 代码仓：交付的脚本放哪儿

状态：已接受（2026-10-20）

## 背景

gravity 执行模型写出来的代码：脚本交付之后，通过某个节点的 mount 运行，源码作为调用参数一起走（gravity ADR-0001/0003）。交付与下一次调用之间，脚本得有地方待着，而这个地方不能是推理层：k10r 才是持有持久数据的进程，gravity 是唯一被允许访问它的客户端（ADR-0007 的消费边界——节点永远不跟 k10r 说话）。

有两样东西很容易和它混在一起，而这张表的形状取决于能不能分开：

- **skill**——agent 知道怎么做的事，结构在图里（前置条件 / 步骤 / 经验 / 验证）；
- **fact**——一条原子论断，带权重和衰减。

脚本都不是。它是**制品**：某一种运行时能执行的字节，加上调用方在执行之前必须知道的那一点点。

## 决策

### 1. 一个可复用代码件一行，键是裸代理 id

`CodeKey { code_id: u64 }`，ns 35。没有名字，没有内容哈希。

- **不要名字**，因为名字是一个命名空间，而这个仓没有分配它的权柄：两个人都写 `login.nu`，解决这件事是治理问题，不是存储问题。id 在写入时分配（`code_id == 0` → 取下一个），调用方永远不自己编身份。
分配器是一个**水位**，不是一次扫描：行上声明 `HighWater(code_id)`，所以「历史最大的 id」是开库时
一次点读，而 unfold 是 NO-OP——撤掉一行永远不会把它的 id 让给下一次交付。用「扫末键」恢复的计数器
恰恰会这么做，而且是在表被清空的那一刻，悄无声息。

- **不要内容哈希**，因为去重从来不是需求。这一行每次调用都会被重读，源码在调用里走，所以没有缓存要失效，「这跟已存的某个是不是逐字节相同」这个问题的答案换不来任何东西。同一个脚本交两次，就是两件交付物、两套参数定义。

### 2. 行里带的是「读源码之前」就需要的东西

`CodeRow { language, description, parameters, source }`。

`description` 是决定 skill→code 链接的依据；`parameters` 是参数定义，以 TEXT 存一份 JSON 文档——**仓不解析它**，因为存储只管存、读的那方负责解释，而交付代码的调用方拥有它的形状。这两个字段都不是 LLM 的检索面：skill 是什么，在图里。

### 3. 语言是行上的数据，且永不默认

脚本是数据，数据有语言。这里不假设、不默认、字段为空也不兜底——调用方把调用路由到服务该语言的那个 mount，而没有 mount 的语言是调用方的错误值。在这里设默认，等于把调用方的路由 bug 变成对别人源码的静默误读。

### 4. 一行是代码，不是 skill

一个登录脚本写一次，很多 skill 都有一步指向它。就是这个方向——多 skill 对一 code 行——才让这张表独立存在。代码若存在 skill 节点里面，那段脚本就会被复制进每一个用到它的 skill。

### 5. `list()` 是起步期的姿态，不是接口

`GET /code` 返回身份 + 语言 + 描述，**不含源码**：够用来挑，不够用来执行。这是「skill 还没链到 code」时期的声明的池读形状；等图里的检索能回答「这个 skill 的某一步指向哪段代码」，那个查询就取代它。

### 6. 存储位置

这张表放在 `memory` keyspace——与图（以及将来的 skill）共用一棵树，用 ns 区分类别，所以一行代码和一条事实不需要两个数据库句柄。API 是 `put` / `get` / `list`。

## 为什么不这样

- **把源码当事实放进图**：六百行脚本不是原子论断。存成一条事实，它就是个穿着边外衣的不透明块；拆成碎片，又需要一套别的东西都没有的拼装规则。权重与衰减——图存在的全部意义——对源码没有任何含义。
- **用 `name` 字段做查询键**：等于请一个仓管不住的全局命名空间进门（重名、改名、大小写），而改名要么断链，要么得回头重写链接。
- **用内容哈希做身份**：按值去重。它还会把只在 `parameters` 上不同的两行悄悄并成一行——而那正是决定「这段代码怎么被调用」的字段。
- **加版本列**：gravity 每次调用都重读这一行，所以源码就是它此刻的样子。真要历史，是再开一行 + 一条说「后者接替前者」的链接，而不是一个要仓去解释的版本号。
- **开一个搜源码的门**：这不是第二个记忆面。代码的检索属于图里 skill 的那条链接，不属于这里的全文搜索。

## 后果

- 代码行是惰性数据：没有级联，没有门暴露的删除路径，没有生命周期。没有谁链接的行，就只是没被引用。
- 调用方存了代码、而执行节点上没有对应 mount 时，会在调用时发现，且很响。这个不对称是故意的：仓不可能知道某个节点能跑什么。
- `list()` 的形状欠一次替换——由图里的检索接替（PLAN 2.8）。本 ADR 把「list 是起步姿态」写在这里，免得有人把它当成设计。
