# ADR-0026：还原只进空的命名空间

日期：2026-11-11
状态：已裁决并落地 2026-11-11

## 1. 背景

湖已经发布出去了（ADR-0014），行能走。没有东西把它们带回来。还原在这里只有两种用途：一个服务从自己的湖整体重建；一部分语料搬进应用刚建好的命名空间——后者就是分析侧取一份副本而不用为每个目的地再写一份声明的路。

两种用途共享一条性质，它决定了其余全部：行不能和已经在那里的行相遇。

## 2. 裁决：先拒绝，再落地

**还原只写本来就是空的命名空间。** 检查在任何一行写入之前跑遍所有目标命名空间；一个非空即整体中止，并点名越界者（`facts in ns 37`）。不合并、不覆盖、不跳过。半还原的表是一张行来自两个时刻的表，它的读者分不出哪一行来自何时。

**两种形状，且只有两种。**

- **不给映射表**——湖里的每张表落回它声明里的命名空间。全量还原。
- **映射表→ns**——只还原点名的表，落到调用方指定的命名空间。这是部分导入，也是数据迁移：目的地由调用方指定，okm 从不自己搬表。

其它（并入既有语料、「还原剩下那些」）是裁决把范围关掉了，不是遗漏。

**空不空问的是键头**，所以面、索引条目与 reduce 行都算占位。若改问文档扫描，还原就可能落在一张索引之上——那些条目指向已经不存在的行。

## 3. 一张表怎么落地

经 `Collection::rebased(ns)`（okm ADR-0062），同一份声明写在新命名空间下，词汇表被 intern 进**目的地**的编号：id 是局部的、标签才是身份，所以同一份湖分别还原进两个命名空间，标签相同、id 不同。边走 `Graph::rebased(ns)`，配一个回答「每张端点表的目标 ns」的解析器——边的端点是 `[ns 2B]` 引用，单搬一条边就指向空气。

边集是按端点对发布的一张张表（ADR-0027），计划里那一条 `facts` 把它们全读了：四张表落成一张图。

reduce 表（log 的 `seq` 水位、code 表的 id 水位）不单独寻址：它们跟着父表的 ns 走，父表被跳过时一起跳过。不带它们的还原会发出还原出来的行已经在用的 id。

## 4. 门在哪里

在二进制里，不在 HTTP：

    krystallizer --config <文件> --restore <目标> [--map <表>=<ns>]...

store 只有一个写者，所以还原是对一个已停止服务的运维动作。它落完湖、打印谁落到哪、然后退出，不开门——一个还原完接着开始服务的进程，等于同一份已被接受的状态有两个写者。

## 5. 代价

还原是发布的反面，仅此而已：没有新增面、没有协议、没有端点。唯一的输入是湖的目录或桶，因此还原不需要源服务还活着——发出去的那一边可以已经没了。

接受的代价：一次调用是全有全无（某张表失败就意味着整个计划重做，因为命名空间已经不再空，半途的运行只能手工清理）；空检查是每个目标命名空间一次扫描，规模由该命名空间装了多少决定——只付一次，且在写入之前。
