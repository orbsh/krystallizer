# ADR-0001: 接口面 — 会话控制、记忆、任务

**状态**：Accepted（设计定案，实现未开始）
**日期**：2026-09-08
**英文版**：[0001-interface-surfaces.md](0001-interface-surfaces.md)

## 背景

skillforge 旧 mem 模块把两件因不同原因而变化的事情混在一起：

1. **会话管线** — 消息追加、prefix checkpoint、压缩触发。自动触发逻辑埋在
   `ConversationMemory.__init__`（`checkpoint_threshold`）：阈值判断和尾提示词
   注入硬接线在 `get_context()` 里。
2. **记忆检索** — flat 长期记忆 + 混合检索，作为辅助上下文注入。

自动触发是**策略**，不是**机制**。策略埋进存储层意味着调用方无法关闭它、
无法按 session 改阈值、无法在其他时机触发压缩（比如一个工作单元结束时，
而不是消息计数到达时）。

## 决策

核心暴露三个接口面。

### 接口面 1：会话控制（被动面 · 短期）

三个可组合的原语，由 agent 显式驱动：

```
branch(fork_point)    从任意前缀点分叉。checkpoint 不可变（前缀模型），分叉
                      零拷贝：分支共享 checkpoint 前缀，增量消息各走各的。
                      两种分叉保持区分——agent 私有的 checkpoint 前缀树，与
                      thread（公开子 channel）：都是带 parent 的日志，差别
                      在可见性。

tail(prompt)          单回合分支。fork → 末尾注入指令 → turn 执行 → 分支丢弃。
                      主会话历史无痕（历史上的"历史纯净性"保证，现在成为
                      结构性质，而不是靠小心代码维持的约定）。

summarize(...)        组合操作：注入压缩指令（经 tail）→ 回收摘要 → 追加一条
                      checkpoint 记录并前移 coverage。压缩是对不可变日志的
                      **追加**——什么都不截断，所以坏摘要是一次重试，而不是
                      永久损失。
```

容器是 **channel 日志**（ADR-0008）：人的聊天与 LLM 对话是同一种形状，agent
的上下文是一个**投影**——checkpoint 记录 + coverage 后的增量 + 未读尾部——
在读取时组装。

**触发策略移到调用方。** 核心只提供原语；*何时*总结（阈值、会话结束、
显式命令）是 agent 侧策略。旧自动触发降格为调用方可选策略之一，
不再是核心行为。

### 接口面 2：记忆（主动面 · 长期）

记忆族是**每个消费者的常备能力**，**以工具形式**提供。承载记忆的那两个面按
**谁发起**命名——被动 / 主动。**完全控制模式 / 辅助模式**这对词退役：它读起来
像"有了完全模式就不需要辅助模式"——好像聊天形态的消费者不需要记忆检索。
事实相反。

| | 被动面 | 主动面 |
|---|---|---|
| 谁驱动 | 循环，每轮一次 | 模型，作为工具调用 |
| 时程 | 短期：当前上下文 | 长期：不在上下文里的事实 |
| 载体 | channel 日志及其投影 | 事实图（flat 记忆是它在图谱化之前的形态） |

短期 / 长期 命名的是**内容时程**，随行作定语；它们单靠自己命名不了面，
因为下面第三种是走被动通道的长期内容。

三种内容：

- **被动（短期）**——循环自己的当前上下文：channel 日志及其按成员的投影。
  会话本身即记忆，检索不参与，模型也从不碰它。
- **主动（长期）**——不在上下文里的事实，由模型**作为工具**查询：对事实图的
  `store` / `search` / `forget`（过渡期也包括 flat 记忆——同一份知识在图谱化
  之前的载体，随图一起撤掉；PLAN Phase 3）。检索结果是**注入**的：与会话并列，
  永不替代会话。
- **初始化（人设 / 风格）**——图派生：k10r 从用户节点出发遍历组装，注入上下文的
  **头部**，即投影里摘要所占的位置。于是它走被动通道、承载长期内容，这正是区分
  "被动"与"短期"的那个情形。装配方式是 k10r 的内部细节：调用方在投影里收到它，
  从不自己组装。它与 ADR-0009 的画像知识不是一回事——那是关于某个成员的一组图
  事实（成员节点 + 它的边，即「频道里的人是谁」），另一种内容。

### 接口面 3：任务（第三个面）

- **它的载体是一个图，不是一张表。** 任务顶点 + `task_links` 依赖边——
  这正是任务森林已经假设的形态（一步一 task 行，绑定到完成它的那次调
  用——gravity ADR-0003 §3），也是多 agent 协调所跑的介质（图替代消息传
  递；并行度来自拓扑，不来自调度器）。
- **任务与事实共用一张图。** 同一信任域：能合的不拆。一种任务节点类型就
  是一个 collection（ns 即类型标记），其 ns 尚未分配。
- **实例态是结构化的、精确的。** 开 / 完是声明的字段，用于枚举（「还有
  几个未完成」）——永不作为近似检索的事实；它随投影下发，因此 gravity
  轮内的派发前检查是本地读（gravity ADR-0003 §4）。
- **为什么它是一个面、而不是记忆面的第四种内容：** 记忆面回答的是「已知
  什么」，走近似检索；任务面是协调与进度介质——依赖顺序、什么可以并行，
  以及（当工作走它时）谁做了什么这份组织台账。问题不同，访问形状不同。
- **它在被动 / 主动轴上的位置：** 任务读走被动通道（随投影到达），完成由
  执行侧在调用点写——完成从不是模型的判断。k10r 持有任务定义、它的边与
  结构化状态。

### 应用形态（一种消费姿态，不是一个面）

三种形态按"谁当主角"分：

| 形态 | Surface 1（会话） | Surface 2（记忆） |
|---|---|---|
| 会话主导（gravity / 聊天类） | 主面：channel log + 投影 | 辅助：检索结果随会话注入，永不替代会话 |
| 记忆主导（mudra / 任务管理） | 不参与，或仅作残余用途（见下） | **全部**：store / search / forget 就是应用的记忆面本身 |

记忆主导**是一种消费姿态，不是它自己的一个面**——现有原语已经覆盖，
变的是姿态、不是接口。这反过来验证了本文的核心边界：核心只管怎么做、不管
什么时候；记忆主导形态里"何时提取、何时存储"同样是应用侧策略（聊天侧这
活归 gravity，任务侧归应用自己的 agent 或确定性规则）。

**应用自身的结构化状态不入记忆管线。** 任务记录、状态字段、到期时
间是应用自己的 KV/表——精确可枚举的查询（"还有几个未完成任务"）不
走近似检索管线，否则"搜索一条记忆"会混进"数一条状态"。k10r 给这类
应用的是**跨会话的事实记忆**：用户偏好、历史决策、做过什么的经验。
近似检索与精确枚举的分界在此，不由调用方配置。

**Surface 1 的残余用途**：应用若有 agent 执行任务的 turn 流（调 LLM
的多轮工作单元），那些 turn 是顺序日志，可用 channel log 承载——键
是任务 id 而非会话 id。这是机制复用，不是聊天语义；纯检索式应用则
完全不碰 Surface 1。

## 后果

- 存储核心从不决定*什么时候*，只决定*怎么做*。mem-core 因此不含策略、
  极易测试。
- 旧的 `checkpoint_threshold` 构造参数和 `get_context()` 内的尾提示词分支
  消失；调用方显式组合 `tail()` / `summarize()`。
- 分支要求 checkpoint 前缀模型严格保持（checkpoint 不可变、消息按调用方
  给的时间戳全序，ADR-0008）。这是存储 schema（ADR-0002）遵守的约束。
- "历史纯净性"（尾提示词永不落盘）是单回合分支的**结构性质**，不是靠
  小心代码维持的约定。
- 承载记忆的两个面按谁发起命名（被动 / 主动）；消费姿态从不新增一个面，
  记忆族对每一种形态都可用。
