# ADR-0014：服务把自己发布进湖，手动导出的门撤掉

日期：2026-11-11
状态：已裁决并落地 2026-11-11。取代 ADR-0013（那篇作为它替换掉的包裹的记录保留）。

## 1. 背景

ADR-0013 把备份做成一次**请求**：`GET /export` 把每张表连同它的 Delta 日志打进一个
`tar.zst`，`GET /export/{table}` 给出一张表，`POST /import` 把一个包裹放回去。备份该有的
东西都在，缺的是两条在实践中决定成败的性质。

第一条：请求必须有人发出。依赖有人记得的备份，只在有人记得的那天存在；真正的失败不是
导出报错，而是两个月没人导出过。

第二条：包裹是一个**文件**。拿它的人解开、得到一个目录，此后每个读者各走各路——格式没错，
但被保存的东西是某块盘上的一份拷贝，把它搬到桶里、搬到仓库、搬到另一台机器，又是别人的活。

okm 的湖这条线对两者都有答案：一张表导出的目录就是一张 Delta 表（okm ADR-0058），日志就是
清单，写入器接受任何键空间——目录或桶（okm ADR-0061）。一个能写一个 Parquet 文件加一个提交
的服务，本身就能当湖。

有一张表不以自己的名字发布：边集按端点对发布成一张张表（`facts__entities__entities` 等），因为
一条 SQL/PGQ 声明里，一张边表只能引用一张顶点表（ADR-0027）。

## 2. 决策：一个 `lake` 节点、一个发布者、没有导出之门

**2.1 配置。** `krystallizer.kdl` 里一个可选的顶层节点：

```kdl
lake {
    target "s3://krystallizer/k10r"     // 或者一个目录
    interval-secs 300
    s3 {
        endpoint "http://127.0.0.1:9000"
        key-env "K10R_S3_KEY"           // 环境变量的名字，绝不是密钥本身
        secret-env "K10R_S3_SECRET"
    }
}
```

`target` 是**一个** url：`s3://bucket/prefix` 是桶，其他都是目录，写入器自己适配——差别是
一种存储实现，不是 k10r 里的一条代码路径。`s3` 段只给桶用，带一个 endpoint（缺省 = AWS）
和持有密钥对的环境变量名。秘密永不进文件；这条规则比本 ADR 更早，这个节点不例外。

**没有这个节点就是开关本身。** 没有 `enabled false` 这种写法：服务要么有湖要么没有，
"配了但关着"是一种会说谎的状态。

**2.2 发布者。** 一个任务在门旁边跑——开门时一次，之后每 `interval-secs` 一次。一次把它
每张表都拷出来（声明的表 + 派生 reduce 表），每张表发布成一个 Delta 版本：`add` 是这次的
文件，`remove` 是它替换掉的那个文件。所以湖里是**当前状态**：每张表一个活跃文件、每个间隔
一个版本，提交落地就删掉被替换的文件。

两段刻意分开。存储的锁只在"把一张表拷进内存"时持有，随即释放；发布随后在阻塞线程上逐表
进行。慢的桶不该变成慢的服务。

**2.3 门撤掉。** `GET /export`、`GET /export/{table}`、`POST /import` 删除，连同包裹格式与
`bundle` 模块。ADR-0013 被取代：它对格式的推理（由声明生成的 Parquet、Delta 元数据、不引入
第二套存储）原样留在本决策里——被撤掉的是**传输**，因为"服务自己写一个文件系统"不该是调用方
需要索取的东西。

**2.4 失败是一条日志，启动除外。** 打不开的湖——坏 url、拒绝服务的存储、名字指到未设置环境
变量——是**启动**失败。运行中发布失败只记日志、下个间隔重试：库里没变，下一次快照带同样的行，
湖落后一个间隔而不是永远不对。两种情况都不停止服务。

**2.5 schema 说了什么。** 文档表的 Delta schema 标记它的 key 列（`okm.key`），读者据此把变更
表折叠回当前状态（okm ADR-0058）。图的边批表与两张 reduce 表不带标记：它们的身份不是本服务能
宣称的——一条边的 key 是边集被索引的那个三元组，一行 reduce 是一个累加器而不是文档。

## 3. 后果

- **没有恢复路径。** 恢复现在意味着"把湖读回来"，那是另一件活：它要按同一条写契约把湖里的行
  落地，还要决定一个非空的库该怎么办。刻意留白——本 ADR 撤掉的几扇门是唯一的恢复通道，而
  半个恢复比没有更糟。
- **湖保留历史。** 每个间隔一个版本，不设上限。裁剪是 `okm-lake vacuum` 对同一个 target 的活，
  一个镜像该留多少历史是运维的判断。
- **依赖长在 okm，不在这里。** S3 客户端在 `okm-lake` 的 `store` 模块后面；k10r 传的是一个 url、
  一对密钥和字节。
- **一次发布是一张完整快照。** 对这个规模的服务这是诚实的形状（表小，代价是一次读）；等它不再
  成立，答案是 okm 的变更日志那条路，而不是一个更聪明的快照。
