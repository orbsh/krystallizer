# ADR-0004: 提取管线留在 Python — 核心零 LLM 依赖

**状态**：Accepted（设计定案）；归属已被 [ADR-0007](0007-consumption-boundary.zh-CN.md) 取代——无 Python 层，LLM 编排归 gravity；确定性 `ingest(fact)` 接口面与融合拆分照旧成立
**日期**：2026-09-08
**英文版**：[0004-extraction-python-boundary.md](0004-extraction-python-boundary.md)

## 背景

graph-memory 设计定义了两阶段提取管线（规范化 → 分类提取为原子事实），
两个阶段都有 LLM 调用和成本策略（阶段 1 小模型、阶段 2 强模型、短输入
合并为单次调用）。写入时融合流程（域外实体收敛）也涉及对小候选集的
一次 LLM 决策。

问题：LLM 编排放 Rust 核心里，还是 Python 层？

## 决策

**mem-core 接收结构化 KDL fact；它永不调用 LLM。**

- 两阶段管线、实体融合的 LLM 决策步骤、主动记忆判据（针对性 × 概括性）、
  一切 prompt 工程都在 Python 层（skillforge 侧，后续是 mem 适配包）。
- 核心的入库面是确定性的：`ingest(fact)`，其中 `fact` 已从 KDL 解析
  （`head <类型> <实体值> [props] / rel <关系> [props] / tail <类型>
  <实体值> [props]`）。
- 融合在核心内按此拆分：
  - **域内实体**（组织成员、项目、任务、商品）：稳定 id 确定性直查——
    零 embedding、零搜索、零 LLM。
  - **域外实体**：核心提供便宜的一半——embedding 检索返回候选事实
    **及其锚定的实体节点**——调用方（Python）跑昂贵的一半（LLM 判断：
    复用节点 / 合并去重 / 新建节点），再带着决策调 `ingest`/`link`。

## 理由

- 核心保持确定性，不需要 mock 或录制的 LLM fixture 即可完整测试。
  存储层的每一条性质都能精确断言。
- LLM 编排是快变关注点（模型、prompt、成本策略每周在变）；存储 schema
  是慢变关注点。分离让两者各按各的速度演进。
- Python 已拥有 agent 集成（工具注入、尾提示词撰写、checkpoint 策略）。
  提取是同类工作——属于那里。
- KDL fact 格式是跨界契约。它是 wiki 为原子事实定的权威序列化格式，
  可确定性渲染为 Mermaid/Cytoscape 供检查，Rust 侧解析就是普通的
  `kdl` crate 调用。

## 后果

- mem-core 零 LLM 依赖，入库路径零网络依赖；核心里唯一的网络调用是
  embedding API（ADR-0003）。
- Python 适配层是交付面的一部分（非一次性 demo）：管线编排、KDL 生成、
  融合 LLM 决策、调用方触发策略。
- 未来若出现非 Python 消费方（mem-server），由它重做编排层或对接
  Python sidecar；核心 API 不变。

## Update（2026-10-14）：图的入图判据；网络调用附注

调用方判据集（specificity × generality）新增一条：**能被"代码化"的
记忆才值得进图——它有规范名，且至少有一条可类型化的关系。** 理由是一
条论据而非偏好：代码域是图检索被证明有效的地方，而代码白送的恰好是这
两样——(a) 每个东西一个规范身份，(b) 有类型、有方向的关系（wiki
graph-memory「为什么图有效：代码域的存在证明」）。两样都没有的记忆
（闲聊、无锚点的印象）进图只会稀释权重：没有身份可供链接，关系也无从
类型化。它唯一有的东西——语义相似——是入口层的事，不是图的事。

后果：图的成本条件是**建构**——身份（规范名 + 别名条目）与关系类型化
是成本所在，跳过它们的入库只会产出孤立节点，而不会变成"检索差一点"。
这条 gate 限制的是"什么能拿到节点"，从不限制"什么可以被存储"：flat
memory 照样全收，而入图判断本身归调用方（它是一条判据，与
specificity × generality 同类）。

网络调用附注：ADR-0003 的 embedding 问题已定案为内置本地模型
（ADR-0003 Update 2026-10-14），因此下面后果节"核心里唯一的网络调用是
embedding API"一条不再成立——核心的外向网络面现在是空的。

## Update（2026-10-16，事实由模型的主动添加产生，不由一个提取阶段产生）

上文背景里的两阶段管线（规范化 → 分类提取，各自带 LLM 调用）作为机制退役：
事实不是被另一趟单独提取出来的。**模型主动添加记忆，在轮内**——记忆工具就是
生产者，那次调用怎么接是调用方的事（ADR-0007）。本文已经定下的东西不动：入口
仍然是「解析后的 KDL 交给确定性的 `ingest(fact)`」，fusion 的切分照旧（域内
id 确定性解析；域外的便宜半边是 embedding 检索 + 锚定实体节点，贵的那半边是
调用方的决定），而 specificity × generality 这条判据现在就是模型决定添加时
自己遵循的一条规则，不再是某个管线的阶段。
