# 0023 — 代码行是一个顶点

> **语言：** [English](0023-a-code-row-is-a-vertex.md)（主） · [中文](0023-a-code-row-is-a-vertex.zh-CN.md)

**状态：** 已接受并落地（2026-10-31）。门、闸与测试同批落地。
**日期：** 2026-10-31
**修订：** ADR-0012（代码仓的身份）。

## 背景

gravity ADR-0003 §3 说：完成是**调用点**写下的，永远不是模型的判断。所以派发一步之前，gravity 必须知道这一段代码关掉哪些未完成的任务。它要的绑定是一条事实——

```json
["run the migration", "task", {}, "finishes_on", {}, "code-7", "code", {}]
```

——而事实只够得着**顶点**。代码行并不是顶点：ADR-0012 给了它一个 ns 35 里的裸代理 id，只按数字寻址，别的什么都不认。于是这条绑定无处落脚，而绕开它的每一种办法，都是在跟地址空间讲价：

- **再加一种端点**（mem-core 的 `Endpoint::Code(u64)`）：为一个消费方的关系，让解析器、渲染器、删除路径和每一个解端点的读者都学会第三种词汇。
- **改绑到 skill**（skill 确实是顶点）：步序没地方放——多步脚本会因为在第 3 步做的功，在第 1 步就把任务关掉。
- **放到任务的状态表当字段**：给一张已有数据的表加列是静默的布局迁移，而且把关系降级成列。
- **新开第三张表**（`[scope][node_id] → code_id`）：这是 k10r 自己的写法，不用迁移，但等于给已经知道怎么装的东西再造一套平行地址空间。

四条都是在躲「把代码搬进图里」这件事。搬比它们都便宜，而且它把问题关掉，不是搁置。

## 决定

**1. 代码行就是普通顶点。** ns 36，`kind = "code"`，和其他所有节点同一个集合——任务和 skill 都在那里（ADR-0021、ADR-0015）。顶点名 `code-{id}`，`{id}` 就是 code id：图按名字寻址，调用方按数字寻址，名字除了这个数字不承载别的。

**2. `code_id` 不变。** skill 的 `steps[].code_id` 照旧装它，gravity 照旧按数字取，一行代码保持它被写入时的那个 id。变的只是这个数字住在哪儿：它现在长在一个节点上，所以事实够得着它。

**3. 载荷搬到顶点旁边（ns 35，边表）。** 键 `[scope][code_id]`：language、description、parameters、source。**在场即意义**——没有表的节点不是代码——载荷不进顶点的 props，因为脚本源码不该是每个读实体表的人都要解的一段动态数据。id 分配仍是原来的水位：写过的最大 `code_id`，所以删掉的行不会把 id 腾出来复用。

**4. 门按 scope。** `POST /code/{scope}` 写入并回答 id，`GET /code/{scope}/{code_id}` 读取，导出/导入把边表当作 `code` 表，和语料里其它表一起走。scope 不是装饰：顶点活在那个 scope 的图里，没有 scope 的代码行就是个无处安放的节点。

**5. 绑定在开启时声明，写成事实。**

```text
POST /tasks/{scope}  { "name": ..., "finishes_on": [code_id, ...] }
```

门为每个 code id 写一条 `finishes_on` 边——普通事实，不加动词、不加表。三条规矩要紧：

- 没交付过的 code id 按名字**拒掉**（400）。绑到空处是调用方的 bug，而造一个 `code-99` 幽灵顶点比报错更糟。
- 重复声明同一条绑定是幂等的（写入回答 `Bumped`），而且再开一次已存在的任务仍然不动它的状态——这才让后一轮能给自己上一轮开过的任务补绑定。
- 绑定只增不改。撤掉一条绑定是撤回一条边，没有门假装能做。

**6. k10r 不关闭任何东西。** 列表对每个任务报出 `finishes_on: [code_id…]`（从边读出来，不存第二份），由 gravity 在那次成功的调用点关掉任务。仓负责回答，执行者负责写。

## 为什么不

- **`Endpoint::Code`**：见背景。新增一种端点是改图的地址空间，代价由所有读者分摊，换来的只是一条关系写得出来。
- **源码进顶点 props**：props 是读节点的人都解的东西；脚本是载荷，载荷进边表（ADR-0019 对向量边表的规矩，这里再用一次）。
- **有语义的 `name`**（描述转成的 slug）**：改名会断掉按名字指它的边，而数字本身已经是身份。

## 后果

- 实体表每行代码多一行，这一行出现在每一次图读取和每一份备份里。一个 bundle 的实体数是「事实的节点 + code 顶点」，读恢复报告时要知道这件事。
- `graph --code vertex` 从查表变成遍历：事实终于能说「哪段代码属于什么」，gravity Phase 5 的计数器（某步跑了多少次）也有了落脚处——落在真正跑过的那行代码上，不只在 skill 上。
- 一行代码是两次写入（先顶点、后边表）。顺序是故意的：失败只会留下一个惰性节点，绝不会留下一张没人够得着的表。
- ADR-0012 主张「不具名的身份」的理由仍然成立——没有任何东西缓存名字，调用方每次调用都重读这一行——但名字现在由图给，是合成出来、由 id 推出来的，不是调用方提议的字段。
