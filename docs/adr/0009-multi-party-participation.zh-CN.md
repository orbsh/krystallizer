# ADR-0009: 多方参与——成员身份、画像与插话策略

**状态**：Accepted（设计定案，实现未开始）
**日期**：2026-09-22
**英文版**：[0009-multi-party-participation.md](0009-multi-party-participation.md)
**扩展**：ADR-0008（channel 日志、投影、策略引擎）

## 背景

ADR-0008 统一了容器（channel 日志）与 agent 上下文（投影），并定义了
压缩策略引擎。两种消费形态被留成隐含：

1. **单人 + agent**——退化形态，agent 全职在场：一条用户消息推进
   投影，每个回合都走「组装 → 推理 → 回复」。所有触发（压缩、提取）
   都挂在回合边界上。
2. **多方 + agent**——agent 是 channel 的**成员**，不是主持人。
   消息流不等 agent：成员们互相说话时，agent 在场但沉默。上下文
   组装与发言回合解耦；开口之前，agent 要拉的是「自己上次发言之后
   channel 里发生的全部」，不只是对自己的 @。

第二种形态带来三个 ADR-0008 未覆盖的需求：

- 投影序列化必须携带**每条消息的发送者身份**。一对一形态下
  user/assistant 交替就够；N 成员时，模型视角里的每条「user 消息」
  可能来自不同的人，不标注身份，买家和客服会被合成一个声音。
- 成员身份在显示名之外还有**语义层**——谁是客服、谁是买家——这是
  用户画像知识，不是 channel 数据。
- 发言不再只由被点名触发。多方 channel 里的 agent 需要插话策略：
  一个延时预算远紧于压缩的被动触发。

当前核心没有任何画像存储：flat 记忆表（`MemoryRow`）只有自由文本，
也没有任何 ADR 给 persona 知识安排过位置。

## 决策

### 1. 成员身份：两层

- **身份层（结构化，进成员表）**——member_id → 显示名 + 角色标签
  （客服 / 买家 / agent 自身）。这是确定性数据；k10r 的序列化路径
  在组装投影时给每条消息前缀 `[显示名]` 归属。无模型参与。
- **画像层（语义，进全局记忆）**——对一个人的长期理解：偏好、
  行为历史、关系背景。画像**跨 channel 有效**（同一个人在售后
  channel 和售前 channel 是同一个画像），所以归属是全局记忆，
  不是任何 channel。

  存储：flat 记忆的受管类别（`kind=profile`），由既有提取管线
  （ADR-0004）增量维护，由既有权重体系（ADR-0005）治理——常被
  引用的偏好变重，过时的衰减。不需要新表；agent 组装上下文时按
  channel 当前成员批量取画像事实。

两层保持分离，因为它们因不同原因变化：身份是管理时点的、确定性的；
画像是运行时的、提取出来的。合并会把「可提取、可修订的内容」塞进
序列化路径当作 ground truth 的表里。

### 2. 插话策略：同一个引擎，更紧的时钟

被动参与复用 ADR-0008 的策略引擎，加第三个信号源。三个触发结构上
同构——信号 → 阈值 → 决策（发言 / 压缩 / 沉默）——差别只在延时
预算：

- **显式（@agent 的名字）**：无阈值，回合立即开始。
- **被动插话**：检查窗口是**秒级**，不是分钟——channel 静默 N 秒
  且新内容相关性过阈值，agent 才考虑开口；「避免冷场」等不起
  缓存失效时钟。相关性候选与静默时长是 k10r 的廉价半步；情境判断
  （「要不要插话、说什么」）是 LLM 调用，归 gravity（ADR-0007 的
  边界）。
- **压缩**：ADR-0008 的时钟（对齐缓存失效），不变。

**沉默是常态结果，不是失败情形。** 多数被动触发的正确结局是不开口。
插话决策同样进决策日志——信号值、决定、理由——因为负样本
（「没说话」）正是未来调「不冷场又不多嘴」这组参数所需的数据。
ADR-0008 §4 的决策日志原样扩展覆盖这个触发。

### 3. 什么不变

- 一个容器：多方 channel 就是同一张 messages 表；members 与 cursors
  本来就按成员键控（ADR-0008 §1/§2）。
- 投影契约：组装读 checkpoint + 增量 + 带成员归属的视图；归属是
  序列化时的事，绝不写回日志。
- 触发策略所有权：阈值与时钟在 `krystallizer.kdl`（全局默认、
  每用户覆盖预留），决策落日志，学习等标签——ADR-0008 §4 的条款
  逐字适用。

## Why Not

- **画像作为 channel 属性**：画像活得比 channel 长（一个人、多段
  对话）；channel 域存储会把一个人劈成按 channel 的碎片、查询时再
  合并——那是用派生合并干全局记忆的本职工作。拒绝。
- **画像作为固定字段的专用表**：画像内容开放且演化（偏好、情境、
  关系）；固定 schema 每加一个侧面就要迁移，而提取事实正是提取
  管线已在产出、权重体系已在治理的格式。拒绝。
- **每条消息都做 LLM 插话判断**：逐消息推理是压缩陷阱重演
  （用一次模型调用判断是否值得一次模型调用）。廉价半步（静默时长、
  相关性候选）必须先 gating 昂贵的那次；LLM 判断只在门开时运行。
  作为无条件机制拒绝。
- **角色标签写进日志**：把 `客服:`/`买家:` 写进消息 payload 会让
  归属成为不可变历史的一部分——纠正角色就要动日志。归属挂在
  成员表、序列化时施加；日志保持原始。

## 后果

- members 表增加显示名/角色字段；序列化路径增加逐消息归属。
- flat 记忆增加 `kind=profile` 受管类别；提取管线的输出路由增加
  画像事实这个目的地。
- 策略引擎增加插话触发（秒级窗口）；决策日志增加沉默结果。
- 单人模式不需要任何新机制：它就是「一个成员 + 所有触发挂在回合
  边界」的多方形态。
