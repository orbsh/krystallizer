# 0020 — 一条断言，一条边

> **语言：** [English](0020-one-assertion-one-edge.md)（主） · [中文](0020-one-assertion-one-edge.zh-CN.md)

**状态：** Accepted 并**已落地**（2026-10-27）。依赖 okm ADR-0041（面里带着两端）。
**日期：** 2026-10-27

## 背景

`ingest` 原本只有三种结局：`Linked`、`Rewritten`、`Dropped`。而且只有 `functional` 关系
会与什么东西比较——同源同种类的在册边。多值关系根本没有同一性，于是**同一条**
`(head, kind, tail)` 摄两次就得到两条边：

```text
POST /memories/37  [["acme","repository",{},"OWNS",{},"issues-api","repository",{}]]
  第一次 → {"edge_id":1,"outcome":"linked"}
  第二次 → {"edge_id":2,"outcome":"linked"}      # 同一个事实，第二行
```

每一次摄入都是人的动作时，这还能活。当**回顾**（ADR-0017 §7）开始写事实时就不能了：回顾
从压缩给出的建议切点读起，而那个切点可能落在覆盖点之后，于是同一段材料按设计会被它读到两遍。
每一趟都会把事实再加一遍——在 `recall` 的预算里、在社区规模里、在 head 里都翻倍。

## 裁决

**`(head, kind, tail)` 是一条边。** 同一性在写任何东西之前检查，而 okm ADR-0041 让它成为一次
seek：这一对领衔索引键，所以这次检查与源节点已经有几条边无关。

再次断言分三种去向：

- **`since` 相同、`confidence` 相同** → `Bumped`：事实已经站着，什么都不写，返回在册的
  `edge_id`。这不是拒绝——事实**在**图里，那正是调用方要的答案。
- **`since` 严格更新，或 `confidence` 更高** → `Rewritten`：同一 `edge_id` 就地改写那一行，
  并且这次写会被计数。对同一个事实的新陈述是新消息，权重系统（ADR-0005）要看得到它。
- **函数性关系**在此之上保留它原有的规则：同源出**不同的尾**时仍与在册边裁决
  （`since >` 或 `confidence >=` 胜出，否则 `Dropped`）。

两条规则是**有序的**，不是合并的：同一性说「这是同一个事实」，函数性说「这个事实可以取代
那一个」。

**为什么不「总是累加证据」。** 一趟重读同一段材料的后台分析不是独立证据——那是同一份证据被
读了两遍，把它计数等于每跑一趟就把权重抬一次。只给**严格改进**计数，`write_count` 才仍然
表示「调用方陈述过的东西」。

**为什么 `Bumped` 那条断言带的 props 被忽略。** 在册边的开放属性是在册边的。同一性是三元组；
若允许一次带不同 props 的重复断言就地改写，就等于不声不响地把 props 也纳进同一性，而且第一个
提到这个事实的回顾趟会拥有此后每个读者那份拷贝的属性。

## 后果

- **重读是安全的。** 回顾把它找到的东西写下去，而它们落在已经站着的那条边上。
- **结局词汇变成四个**——`linked / rewritten / dropped / bumped`——出现在门的答案里、
  `commit_memory` 的描述里（模型读那串字），以及 `MODELING` 里。
- **`write_count` 从此表示「不同的改进」**，而不是「被提到过几次」。
- **在 okm ADR-0041 之前写下的 store**，对同一条三元组会两次报 `linked`，直到它的面被重建；
  那两行仍然是两行，这条记录不合并它们——`reindex` 重写的是索引，不是语料。
