# 0021 — 任务是顶点，另带一张任务单

> **语言：** [English](0021-tasks-are-vertices-with-a-sheet.md)（主） · [中文](0021-tasks-are-vertices-with-a-sheet.zh-CN.md)

**状态：** Accepted 并**已落地**（2026-10-27）。三条门、三个工具、turn 开头的列举随它一起。
**日期：** 2026-10-27

## 背景

固定工具清单（ADR-0004）写着三组：记忆、技能、任务。前两组存在，第三组在这条链里**没有
任何存储**——`gravity` 是纯胶水（无存储）、`prism` 只持有身份、`aura` 是域——于是任务除了记忆
核心没有别的落脚处，而 k10r 里没有任何东西知道任务是什么。

形状并不显然，这里前两个方案都是错的。

**一行一任务 + 状态面**（任务表、每任务一行、按状态索引）是传统任务管理器的样子。它完美回答
「哪些还开着」，却回答不了「这个挡住谁」——而依赖、父子、标签、交叉引用**就是**任务的内容。
那些是边。

**任务独立成一个集合**（ns 44 当顶点表）能给它边，代价是多一种顶点类型：每个写边的地方、
每个解析器、每条删除路径都要学会第二种端点。

## 裁决

**1. 任务是事实图里一个普通的顶点。** ns 36 里 `kind = "task"`，与其它所有节点同一个集合，
也与 skill 同一个集合。依赖是 `link`，父子是 `link`，标签是 `link`，指向 issue 或文件的引用
还是 `link`——而关于任务的事实就是事实：

```json
["task-12", "task", {}, "depends_on", {}, "task-9", "task", {}]
```

这些都不需要新机制：解析器按类型名按需 intern 一个节点，正是 `skill` 的做法（ADR-0015）。
任务的名字就是它的身份；一条事实点名了一个还不存在的 `task`，它就存在了——**被当作活提到，
就是活**。

**2. 会变的那部分在一张副表里（ns 44）。** 同一个 `EntityKey`，`NodeVector` 的模式
（ADR-0019）：键字节完全一致，没有连接表，一个 batch。

```text
ns 44  TaskSheet  [scope][node_id]
         state       open | doing | blocked | done     （闭集，不在其中直接拒）
         next        下一步做什么，生产者自己的话
         created_at  开单时调用方的时钟
         updated_at  最后一次迁移时调用方的时钟
         #[ok_index(by_state { fields(state) })]  ->  [state][scope][node_id]
```

为什么是副表而不是 props、也不是行上的列，三条：

- **在场即含义。** 任务单存在当且仅当这个节点是任务。顶点对每种 kind 保持同样的字段——反过
  来的做法会让语料里每个节点都带上任务的列，那正是 ADR-0019 为向量撤销的错。
- **状态要被枚举，不是被检索。** 「哪些开着」是精确问题，面能回答它，而 okm 对动态 prop
  没有索引。状态放在 props 里，等于永远扫全部任务再在内存里过滤。
- **生命周期不同。** 顶点跟着事实活，任务单跟着活干。一个可以被退役而不动另一个，而且两边
  的写互不触碰对方的行。

**3. 三条门，因为有三件事不是边。**

```text
POST /tasks/{scope}                     开单（按名字幂等）
POST /tasks/{scope}/{node_id}/move      状态与/或下一步；缺席即不动
GET  /tasks/{scope}?state=open          枚举
```

**对已存在的任务开单是「重述」，不是「移动」。** 名字就是身份，所以第二次开单是同一条事实的第二次
陈述——若在那条门里改写任务单，就是那种安静的 bug：一次重试的工具调用会把任务从 `doing` 拖回
`open`、清空下一步、重置它的时钟，于是**唯一一条含义就是「这活存在」的调用，成了丢掉这活进度的
调用**。要改任务，走 `/move`。同理，声明永不改节点的标签：对一个已经是 person 或 skill 的名字
开单会被拒，而不是被转换。

刻意**没有**依赖门、父子门、标签门：那些是事实，给一张图配第二套词汇，等于多一样要保持同步的
东西。`/move` 用动词段，和 `/touch`、`/promote` 一样——「对这个节点做点什么」只有一种门形，
调用方不必知道某个动作选了哪个 HTTP 动词。

**4. 状态是闭集。** `open`、`doing`、`blocked`、`done`；别的一律在门口拒掉。一个存进没人查的
状态名下的任务，就是一个没人找得到的任务——这种失败是静默的，而静默正是打错字会得到的。

**5. 一轮对话从知道什么还开着开始。** `gravity` 列出 open 任务，作为一段 system 消息放在新消息
之前。尽力而为：存储答不上来不算这一轮失败，模型还可以用 `list_tasks` 问。

## 后果

- **agent 从此能驱动自己。** 在这之前每一轮都从零开始：它知道说过了什么，不知道还欠着什么。
  那正是第三个工具组存在的理由。
- **跨会话的活在一张图里。** 对话里提到的任务、用事实写的依赖、标签、父子、笔记都在一处——
  而关于某任务的 recall 能找到它的事实，因为它们**就是**事实。
- **`state` 不是事实。** 迁移任务覆盖任务单、不索引别的东西；图里不累积状态，所以「被挡住了
  多久」用历史答不出来。真要那个，是新增一种边，不是给状态列加日志。
- **`next` 是存储不解析的自由文本。** 与技能步骤同一条规则（ADR-0012 §2）：形状归生产者。
- **任务没有 owner 字段。** 归属在需要时是一个 person 节点加一条边，这正是这张单不会长成
  任务管理器的原因。
