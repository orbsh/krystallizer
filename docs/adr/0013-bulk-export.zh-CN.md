# ADR-0013：备份就是同一扇门上的 Parquet 导出

日期：2026-10-20
状态：已裁决并落地 2026-10-20——文档表已导。事实表欠着（ns 37，见 §4）。

## 1. 背景

ADR-0007 定的是：批量读仍然是同一 HTTP 边界上的读——没有管理 CLI、没有第二套存储、不
在数据旁边自创一种转储格式。备份正好就是这样一次读（「这张表的全部」），它留下的问题是
**格式**，不是传输。

两种答法。自创一种（k10r 写 JSON 或 CSV dump），或者用 okm 已经有的桥：okm ADR-0007 的
eager Arrow 导出按行**声明**把一个 collection 变成 `RecordBatch`，`parquet_io` 再写成文件。
只有第二种不会漂：列由「生成键编码与载荷帧的那同一份声明」生成，所以改结构是一处改、
改名不可能只改一边。

## 2. 决策

**`GET /export/{ns}`——一张表、一个文件、`application/vnd.apache.parquet`。**

- ns 就是这张表的地址，和别处一致（ADR-0010 §1 的 ns 词汇）。`Content-Disposition` 把文件名
  定为 `ns<N>.parquet`，于是一目录的导出不用打开就能看出各自是什么。
- schema 是 okm 的，不是 k10r 的：带类型的列、`Vocab` 字段导出成它的**标签文本**（没有名字的
  id 导出为 NULL）、定宽声明字段按宽度、`Vector` 字段按元素展开。k10r 只决定导出哪张表、
  文件落在哪，别的不碰。
- okm 的 `export_parquet` 写的是**路径**，所以这扇门写进临时目录再把字节回给调用方。答案是
  请求时刻的**快照**：响应构造完成之后才写进来的行不在这个文件里。
- 本服务没有的 ns 是 404。空表是 200 加一个合法的空 Parquet 文件——「这张表是空的」本身是
  备份该带的信息。

**粒度：按 ns，一表一文件。** 另一种答法是「一次备份一个归档包」，它换来单一文件，代价是引入
一种容器格式、在恢复路径上多一个解析器，并且看不出是哪张表出了问题。一表一文件还意味着
局部恢复就是恢复一张表，而不是一次解包作业。

## 3. 为什么格式不归 k10r

k10r 自写的 dump 等于把同一批行再描述一遍：它得跟着声明同步维护，它会把 k10r 的字段名带进
任何读这份备份的东西里，而且它过不了备份唯一的那道考题——**能被不是写它的那个程序读出来**。
Parquet 免费给出这一条（polars、duckdb、pyarrow 都能开），而「Vocab 导出成标签」这一规则
让文件不依赖存储的编号表就能读懂。

## 4. 事实表是 501，而现阶段这是正确答案

边不是 `Document` 行。一条边活在图的条目形状里（`EdgeKey` + `EdgeBody` 帧，`GraphEncode`），
而 okm 的桥只读 `Document` 集合。所以 `GET /export/37` 答 **501 并带上原因**，不是一个空文件、
也不是 k10r 自创的 dump：读不回存储的「备份」不叫备份，而在唯一真正的导出旁边再放一种格式，
比留下一个被点名的缺口更糟。

修法在 okm：给 `Graph` 一个导出面（同样的 `RecordBatch` 形状，边列来自 body 加载荷声明的
字段）。在它存在之前，k10r 的备份是「除事实之外的全部」——这句话该写在文档里，而不是变成
一次意外。

## 5. 后果

- 检视和手工恢复不需要 k10r：文件里带的是标签，不是编号。
- 结构化日志（ns 41）可以在裁剪丢掉行之前归档——那张表里，导出同时也是唯一的长期记录。
- **恢复没有实现。** okm 有 `import_parquet`，接它是一扇单独的门，有自己的裁决：落到哪个 ns、
  覆盖还是合并、以及文件里的 `Vocab` 标签在目标词汇表里不存在时怎么办（okm 的导入选择拒绝
  而不是猜——那个拒绝是设计，不是疏漏）。
- `parquet` feature 在本构建里常开。这扇门是一等表面不是可选附件，所以依赖（arrow + parquet）
  在构建期付一次，而不是变出第二个、构建方式不同的二进制。
