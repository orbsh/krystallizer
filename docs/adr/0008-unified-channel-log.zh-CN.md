# ADR-0008: 统一 channel 日志——agent 上下文是投影，启发式压缩

**状态**：Accepted（设计定案，实现未开始）
**日期**：2026-09-22
**英文版**：[0008-unified-channel-log.md](0008-unified-channel-log.md)
**修订**：ADR-0001（summarize 的截断步骤）、ADR-0002（session 消息键）、ADR-0006（session 读写形态）

## 背景

ADR-0001 在 agent 私有的 session 文档上定义了会话控制
（branch/tail/summarize），ADR-0002 把 session 消息键定为
`(ns, user_id, session_id, seq)`。两种消费形态被留成了两个容器：

1. **人的聊天**——多人 channel、私聊（两成员 channel）、已读游标、
   锚在消息上的 thread、话题标签。
2. **LLM 对话**——agent 的上下文窗口、长度控制（压缩）、与主动
   记忆提取的配合。

两者消费的是同一个底层对象——有序消息日志——但草案把它们
建成了两个容器。这意味着「拉增量」「压缩」「已读」各实现两遍，
而两套实现的差异（coverage 对未读游标、checkpoint 对历史）恰好
都是投影层能吸收的。

同一区域还暴露了第二个缺陷：ADR-0002 以「同一毫秒的两条消息不能
乱序」为由拒绝墙钟时间戳、采用每 session 单调 seq。该理由只考虑了
跨发送方乱序，漏掉了反向风险——共享计数器分配的 seq 与因果无关，
而回复的时间戳必然晚于它所回复的消息（回复方必须先看到它）。

## 决策

### 1. 唯一容器：channel 日志

人的聊天与 LLM 对话共享同一个存储原语：**append-only 的 channel
日志**，键 `(ns, channel_id, timestamp)`。除此之外没有第二个容器。

- 私聊 = 两成员 channel。群聊 = N 成员 channel。
- agent 的「session」不是容器，是 agent **自己的投影**：
  checkpoint 记录 + coverage 点之后的增量 + 未读尾部。
- thread 是锚在 `(channel_id, timestamp)` 上的子 channel——同一张
  messages 表加 parent 指针，公开的第二维度。它不是 agent 的分支。
- 话题标签是消息行上的**二级索引**（OKM index entry；标签树沿用
  既有的 tag-tree 设计），不是第三种容器。论坛式消费（按主题拉取）
  与 IM 式消费（按时间跟随）是同一份日志上的两条读路径。

### 2. agent 的上下文是投影

agent 从不拥有、截断、改写日志。它的上下文在读取时组装：

```text
channel:  [m1][m2][m3][m4][m5][m6][m7]...
                        ^
agent A: checkpoint(c1: m1..m4 的摘要) + [m5][m6][m7]
agent B: 游标在 m3 → 未读 [m4][m5]...
```

- **压缩是追加，永不截断。** summarize = 经 tail（ADR-0001 的单回合
  分支）跑摘要 → 追加一条 checkpoint 记录（coverage 位置 + 摘要
  文本）→ 投影此后读 checkpoint + coverage 后的增量。日志本身
  永不收缩；摘要错了可以重跑，历史可以随时重新分割重压。这打破了
  「压缩必须吞下全部历史」的定势：每次压缩覆盖有界的一段，摘要
  质量有界。
- checkpoint 按成员键控——`(ns, channel_id, member_id, timestamp)`
  ——它是私有投影物，不是共享日志内容。两个 agent 挂同一 channel
  时各自独立压缩，互不干扰。
- 已读游标 `(ns, channel_id, member_id) -> 最后已读 timestamp`
  同时服务 IM 的未读数与 agent 的增量拉取：一个机制，两个消费者。

本条修订 ADR-0006：「fetch 全量 session、写回 session」改为
「append 自己的记录、读自己的投影」。无状态循环的性质不变——
持久化与组装仍然沉入存储层，变的只是读写形态；循环依旧不改写
历史，且现在存储层从结构上禁止它这么做。

### 3. 时间戳定序（修订 ADR-0002 的 seq）

消息排序用 **gravity 写入时打的时间戳**，不用单调计数器。

- **免费拿到因果一致**：回复必然晚于它所回答的消息（回复方先看到
  它），物理时钟给出与因果偏序一致的全序——带真实时钟的 Lamport
  clock 论证。共享 seq 计数器没有这个性质：回复可能落在它逻辑上
  跟随的并发消息之间。
- **跨发送方乱序无害**：两条无因果关系的消息是并发的，相对顺序
  不改变任何语义。
- **单一时钟权威**：gravity 的时钟就是 channel 的时间。对话流跑在
  内部时间上；用户客户端的时钟从不参与定序（客户端时间戳至多是
  展示元数据）。这消除了多方时钟偏移问题：只有 gravity 的时钟需要
  正常，而偏移不可能破坏因果——回复永远在它所回答的消息写入之后
  才写入。
- **同毫秒突发**（gravity 同时服务多用户/多 channel）：键追加
  决胜段——`(ts_ms u48, sender_hash u8, sub u8)`——宽度稳定，不影响
  max-gap 计算。
- **max-gap 变成时间差**：时间即序之后，最大间隙就是一次 range
  scan 里相邻条目的最大时间差——不需要第二索引，不需要 seq→时间
  反查。
- 存储成本净省：事件本来就该带时间戳，独立的 seq 列消失。

### 4. 压缩是参数化的策略引擎

压缩触发是启发式的，绝不用 LLM 判断：用 LLM 判断「话题是否转换」
花一次推理，判断完还得再花一次摘要——两次模型调用买一次机会。
分界点必须是零成本的。启发式如下：

- **缓存时钟触发**：prompt cache 的 TTL 快到期时（如 1 小时缓存的
  第 50 分钟空闲）且上下文有分量（超过下限百分比）→ 压缩——缓存
  反正要失效，压缩零成本。上下文只有几条、不到下限 → 不压；时钟
  是免费信号，不是义务。
- **预算触发**：到中段阈值（如上下文的 50%，而非 90%——阶梯定价
  低档便宜得多，且压缩质量随跨度增长而劣化；早压让每次摘要小而好）。
- **max-gap 分界**：在 coverage 头之前的有界窗口内，取相邻消息
  时间差最大处切开——对话停顿是话题转换的可观测痕迹，零模型成本。
  触发与分界要互相印证：若 max-gap 恰是当前的沉默（触发触发的那个
  空闲本身），不压。

**所有阈值是参数，不是常数。** 策略配置（`krystallizer.kdl` 的全局
默认）持有每一个数字：缓存比例、预算百分比、窗口边界、最小上下文
下限。每用户覆盖是预留的第二层（查一个覆盖表，miss 落到全局默认）
——结构上现在就预留，数值将来手动或自动填。

**决策日志先于模型拟合。** 回归模型需要标签（「这次压缩好不好」），
标签现在不存在；没有标签的拟合拟合的是噪音。每次压缩决策落一条
结构化记录——参数快照、触发信号值、分界位置、压缩前后 token 量
——这就是未来的训练集。反馈信号真实出现后学习回路再闭合；策略
引擎今天的「引擎」指可参数化 + 可审计，不是自适应。

### 5. 与主动记忆提取的分工

两者消费同一份日志；服务不同层，不合并：

- **summarize** 服务上下文：有损，为模型的工作集，受回合内延迟预算
  约束。
- **提取**服务跨 session 记忆：原子事实进 flat memory / 图，异步，
  在回合路径之外。提取 worker 跟在 coverage 指针后面跑——日志
  append-only，提取可以滞后、批量、重跑，完全不挤占对话延迟。

分开的根因：质量/延迟预算不同（摘要在回合内，提取在回合外）。

**多方参与**——成员身份（members 表的显示名/角色，归属在序列化时
施加）、用户画像（全局记忆的 `kind=profile` 受管类别，提取产出、
权重治理）、插话策略（同一个策略引擎的秒级被动触发，沉默结果入
决策日志）——由 ADR-0009 规定。单人形态不需要任何新增机制：
一个成员，所有触发挂在回合边界。

## Why Not

- **session 作为第二容器（LLM 对话专用保留）**：拉增量、压缩、
  已读各实现两遍；差异（coverage 对游标、checkpoint 对历史）全部
  能被投影层吸收。拒绝。
- **LLM 判断话题边界**：一次判断 + 一次摘要 = 每次压缩两次调用；
  启发式（最大时间差）零成本且与触发互相印证。LLM 判断只有在它
  连摘要一起替代时才划算——那是「当场压缩」，恰是触发条件要避免的
  形态。作为分界机制拒绝。
- **截断式压缩（主流形态）**：毁掉重跑能力。截断日志上的坏摘要
  是永久的；append-only 日志上它是一次重试。拒绝。
- **现在就拟合策略参数（对决策日志做回归）**：标签尚不存在，拟合
  会追着噪音跑。决策日志是便宜且正确的上半场。预留结构，推迟实现。

## 后果

- ADR-0002 的消息键 `(ns, user_id, session_id, seq)` 被
  `(ns, channel_id, timestamp+决胜段)` 取代；session_id 从键空间
  消失——统一落在这里。
- ADR-0001 的 summarize 失去截断步骤（换成 coverage 前移 +
  checkpoint 追加）；branch/tail 不变，且「branch」（agent 私有，
  checkpoint 前缀树）与「thread」（公开子 channel）保持区分——
  两者都是带 parent 的日志，差别在可见性。
- agent 循环契约（ADR-0006）重述为：append 自己的记录，读自己的
  投影；scale-to-zero 与无状态照旧成立。
- 新表：messages、members、cursors、checkpoints（按成员）、消息
  标签索引。全部 OKM 声明；hex stability test 锁布局。
- 策略引擎是 k10r 侧的纯函数（阈值评估、max-gap 分界、决策日志
  记录）；LLM 调用（摘要）按 ADR-0007 留在 gravity 侧。
