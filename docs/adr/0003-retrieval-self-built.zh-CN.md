# ADR-0003: 检索 — 内置 embedding 模型，向量着陆 + 图遍历

**状态**：Accepted（设计定案，实现未开始）
**日期**：2026-09-08
**英文版**：[0003-retrieval-self-built.md](0003-retrieval-self-built.md)

## 背景

旧检索路径是 ParadeDB SQL：pgvector 余弦 + pdb.bm25 全文 + RRF 融合，
单条查询。离开 PG（ADR-0002）意味着这些扩展不再可用，检索必须在 KV 这
一侧重建。

## 决策

**Embedding：进程内置的本地小模型。** 小模型跑在 k10r 进程内的 CPU 上。
模型身份与数据锁定（不同模型的向量不共享空间，所以持有 embedding 一致性
的是记忆系统，不是任何调用方），且没有端点、没有密钥、没有传输跳——这正是
mem-core「零传输依赖」字面成立的原因。向量以 `Vector<f32>` 帧写入。

**向量检索：每 ns 一份内存表 + 暴力内积。** 语料按 user 分；几万向量装内存
绰绰有余。ANN 只在**实测**语料越过阈值时重开，且 arroy 不是它的默认形态：
arroy 0.6 是 LMDB（内存映射）索引，做不到「序列化进 Fjall」——它自带第二个
存储引擎，正是本文档排除的东西。阈值以下不是推迟，是去掉。

**检索形态是向量着陆 + 图遍历。** 精确的实体名/别名点查（实体名/别名 →
节点 id，一次前缀扫描——图自己的身份面）与向量 top-k 种子进入**同一段**
遍历，遍历展开邻域并按权重排序（ADR-0005，Phase 3/4）。旧的融合得分由
着陆置信下限和一个合法结果「没落地」（调用方不注入记忆）取代。

**词法分支撤销：jieba、倒排索引、BM25、RRF、tantivy 一并去掉。**

- 它买的是**扁平**检索下的 top-k 精度。一旦答案由邻域展开 + 权重序 Top-K
  产生，着陆只需进对连通区，那份精度不是读路径需要的东西。
- 它为那份精度付两项结构性代价：分词绑定单一语言，以及词面精确匹配在同
  义词上必输（要救就得维护同义词表，正是本设计拒绝维护的东西）。
- 它唯一独占的能力——罕见 token 的原样命中（`ADR-0016`、`ERR_021`、
  标识符，小模型对它没有有意义的表示）——移到上面那个键空间点查。那是图
  的身份面，不是第三套检索机制。
- tantivy 同理不引：它要服务的那条分支已经不存在。

塑造早期草案的选型规则仍然成立，只是现在花在图这一侧：简单算法直接实现，
只有复杂算法（PageRank、社区发现）才值得引依赖。

## 后果

- 「functions without boundaries」在主场兑现：过去是 PG 内 UDF 和 SQL CTE
  （混合检索）的东西，现在是普通库代码。
- 完全没有 HTTP 跳：模型在进程内，写入与查询都在本地 embed。去掉远端
  embedding 调用正是让核心的出网面变空的那一步（ADR-0007）。
- bring-up 姿态：实测阈值以下用暴力内积顶替 ANN；ANN 集成不阻塞 Phase 1。
- 没有分词器可控，因此「分词与打分全链路可控」不再是本条路线作出的换取项
  论述。
- PG 退出闸门变成固定查询集上的端到端召回对照，不再是逐分支对 pgvector +
  pdb.bm25 + RRF 的对照（PLAN 1d）。
- `config/krystallizer.kdl` 的 `embedding` 节点在 Phase 1c 落地时去掉
  base-url / api-key-env，改为 model + tokenizer 路径。
