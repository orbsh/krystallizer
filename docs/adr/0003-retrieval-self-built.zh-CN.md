# ADR-0003: 检索 — 内置 embedding 模型，向量着陆 + 着陆到的社区

**状态**：落地（2026-10-17：embedding 引擎——进程内置的本地模型，从一个模型目录
加载——配置面，以及行的向量载体；2026-10-19：着陆表、`/search` 与 `/recall`，
PLAN 1c/1d。模型的选择仍是暂定的：对旧 PG 那套的召回对照在本机仍跑不起来，
所以 PLAN 1d 的 fixture 就是基准）
**日期**：2026-09-08
**英文版**：[0003-retrieval-self-built.md](0003-retrieval-self-built.md)

## 背景

旧检索路径是 ParadeDB SQL：pgvector 余弦 + pdb.bm25 全文 + RRF 融合，
单条查询。离开 PG（ADR-0002）意味着这些扩展不再可用，检索必须在 KV 这
一侧重建。

## 决策

**Embedding：进程内置的本地小模型。** 小模型跑在 k10r 进程内的 CPU 上。
模型身份与数据锁定（不同模型的向量不共享空间，所以持有 embedding 一致性
的是记忆系统，不是任何调用方），且没有端点、没有密钥、没有传输跳——这正是
mem-core「零传输依赖」字面成立的原因。向量以 `Vector<f32>` 帧写入。

2026-10-17 落地：**BAAI/bge-small-zh-v1.5**（512 维、CLS 池化、fp32 约
96 MB），由纯 Rust 的 BERT（`candle`）运行，模型来自 `config/krystallizer.kdl`
的 `embedding` 节点所命名的**模型目录**——三个文件按固定名在目录里找——
且 `KRYSTALLIZER_MODEL_DIR` 可覆盖该值，因为工件住哪里是部署事实而非仓库
事实。这个选择是暂定的：能推翻它的是召回对照（PLAN 1d），而换模型等于换
目录**加上**把整个语料重 embed 一遍——向量不跨模型携带，这正是模型要与数据
锁定、而不是每次调用现选的原因。

向量的载体同一批落地：行的 `embedding: Vector<f32>` 是**任意长度**的 cold
帧（计数随帧走，所以换模型换的是数据、不是 wire——刻意不加 `#[ok_len]`
契约），在源头 L2 归一，于是 `cosine` 就是内积。向量由**进程内**的引擎算
好（服务进程挂上的那个），HTTP 客户端从不发向量；没挂引擎时写的行带**空
帧**——合法的一行，检索侧跳过它，而不是零向量。

**向量覆盖什么（2026-10-23 补充）。** 向量覆盖节点的标签**以及它承载的文本**：
`name`，加上行上有的 `title` / `content` 两个 prop。只嵌标签意味着读者能按
**名字**搜到一个节点，永远搜不到它**说了什么**，于是还得回去读原文档——那恰恰
是事实图要避免的事。两个 prop 都没有的行仍按名字嵌，先于这个约定写下的数据
一个字节都不动。

**引擎是一种「模式」，不是一个实现（2026-10-21 裁决）。** 存储需要的是契约：一句话进、
一个**单位长度**、宽度等于声明 `dimensions` 的向量出。谁来算属于部署事实，所以
`embedding` 节点把它写出来：

- `mode "local"` —— 进程内的内置模型，默认，不变：没有端点、没有密钥、没有传输跳。
- `mode "remote"` —— OpenAI 形状的嵌入服务（`POST {base-url}/embeddings`），于是向量
  可以在有 GPU 的机器上算，而 k10r 仍然自己持有存储、自己的时钟、自己的契约。选这个
  形状是因为这个操作实际上只有**一种** wire 形态（vLLM、sglang、Ollama、LM Studio 与
  各家云 API 都说它）；按厂商各写一份适配，换来的只有维护面。

标签选的是**形状**，不是一个分支：`mode` 是节点的 tag，每种模式的字段集是它自己的
类型，于是另一种模式的字段落在那一行上就是解码错误，而不是校验器必须记得去拒的名字。

接缝是 mem-core 里的一个 trait（`Embedder`），本地引擎是其中一个实现；远程的那个客户端
住在 `mem-server` 里：核心保住自己零传输的面（它拥有契约，不拥有客户端），而已经在跟
消费方说 HTTP 的那层壳去跟模型说 HTTP。两种模式都在**启动时被证明**——缺工件、连不上
服务、回来的宽度与配置不符，都是启动失败，因为一张表里混两个向量空间是存储活不下去的
状态。远程答案**在本侧归一**而不是信任对端；bearer token 由 `api-key-env` 命名
（变量名，密钥本身永不进文件）；请求在那唯一一个客户端线程上串行——这是存储自己的
单写者纪律，不是新加的瓶颈。这个模式付出的代价是延迟：进程内是一次内存操作，远程给每次
ingest 和每次落点各加一次往返。

**向量检索：`okm-vector` 的索引 + 每 ns 一份内存表。** 语料按 user 分；几万向量
装内存绰绰有余，所以精确路径就是亚毫秒答案，不需要别的机器。**索引整条都是
`okm-vector` 的**（2026-10-20 裁决）：今天是精确的（`ExactIndex`），近似形态是
同一个 crate 的事——从它那里取，而不是在旁边另设计一套；本仓不自己规划近似索引、
没有阈值参数、没有索引选项。arroy 被否：arroy 0.6 是 LMDB（内存映射）索引，
做不到「序列化进 Fjall」——它自带第二个存储引擎，正是本文档排除的东西。

**检索形态是向量着陆 + 着陆到的社区。** 精确的实体名/别名点查（实体名/别名 →
节点 id，一次前缀扫描——图自己的身份面）与向量 top-k 种子都只负责着陆；
答案是这些种子所属的**社区**（ADR-0010 §5）：成员走 `by_community` 面，
两端都在社区内的事实走遍历面，按权重排序（ADR-0005），渲染成带 id 的文本。
旧的融合得分由着陆置信下限和一个合法结果「没落地」（调用方不注入记忆）取代。

**词法分支撤销：jieba、倒排索引、BM25、RRF、tantivy 一并去掉。**

- 它买的是**扁平**检索下的 top-k 精度。一旦答案由邻域展开 + 权重序 Top-K
  产生，着陆只需进对连通区，那份精度不是读路径需要的东西。
- 它为那份精度付两项结构性代价：分词绑定单一语言，以及词面精确匹配在同
  义词上必输（要救就得维护同义词表，正是本设计拒绝维护的东西）。
- 它唯一独占的能力——罕见 token 的原样命中（`ADR-0016`、`ERR_021`、
  标识符，小模型对它没有有意义的表示）——移到上面那个键空间点查。那是图
  的身份面，不是第三套检索机制。
- tantivy 同理不引：它要服务的那条分支已经不存在。

塑造早期草案的选型规则仍然成立，只是现在花在图这一侧：简单算法直接实现，
只有复杂算法（PageRank、社区发现）才值得引依赖。

## 后果

- 「functions without boundaries」在主场兑现：过去是 PG 内 UDF 和 SQL CTE
  （混合检索）的东西，现在是普通库代码。
- 完全没有 HTTP 跳：模型在进程内，写入与查询都在本地 embed。去掉远端
  embedding 调用正是让核心的出网面变空的那一步（ADR-0007）。
- bring-up 姿态：扫描就是**精确**的——对 scope 的表做暴力内积——这就是这个规模
  下检索的成本故事；背后没有等着接的近似索引，因为索引形态归 `okm-vector`，
  从不是本仓的 phase。
  **2026-10-19 落地：** `GraphStore::retrieve` + `GET /graph/{scope}/search`——
  每 scope 的内存表（首次使用时从 KV 载入、每次写入即失效、带字节预算与 LRU 淘汰），
  对单位长度向量做内积，`LANDING_FLOOR`（0.35）与"合法空落地"——以及读答案
  （`GraphStore::recall`、`GET /memories/{scope}/recall`）：种子、种子着陆到的社区、
  以及这些社区事实的**一种**表示——按事实预算渲染成带 id 的文本，或 `format=struct`
  时只给数据（ADR-0010 §3–§5）。按权重的
  排序归 ADR-0005。`/search` 是**分析**门（只有落点，供检视），`/recall` 是
  **核心**门（记忆答案）——两类门的划分归 ADR-0007。
  **2026-10-22 修订：** 两扇查询门都是 `POST` 并收**数组**，按同样顺序答数组
  （`POST /graph/{scope}/search`、`POST /memories/{scope}/recall`）；单条 GET 形态撤销。
  模型对同一个回合一次问好几件事，而写门早就收数组——读侧与它对齐（ADR-0001「两扇门都是
  多条」）。
- **三笔代价，以及形态归谁定（2026-10-19）。** 扫描策略只能从算力、内存、
  I/O 里挑一笔付，而且必须是**实测**决定：内存表付内存（~2 KB/向量）、扫 O(N·d)
  ——10⁴ 条是亚毫秒，10⁵ 条在 AVX2 下约 6 ms；IVF 付训练与"重训即重写全部桶键"，
  换来只探 nprobe 个桶；HNSW 付一张持久化的图（删除退化成 tombstone、换模型
  重建），换来对数级跳数，而整条路径本来就只有几毫秒时它什么也没买到。
  **k10r 拿到哪一种索引由那个 crate 定，不是本仓定**（2026-10-20 裁决）：语料
  通过 `okm-vector` 查询，它带什么形态——今天是精确的，将来有近似的就用近似的
  ——就从那里取，快照 blob 落在 okm 自己的面上。这边留下的是**账**，不是算法：
  派生表何时重建（每次写入即失效）、允许多少留在内存（字节预算 + LRU 淘汰）、
  以及落地下限。任何索引都是从行重建的**派生状态**，永不作为第二真相源；arroy
  仍因 LMDB 被否——它会带进第二套存储引擎，而那个 crate 恰好替我们省掉的正是
  这一条。
- 没有分词器可控，因此「分词与打分全链路可控」不再是本条路线作出的换取项
  论述。
- PG 退出闸门变成固定查询集上的端到端召回对照，不再是逐分支对 pgvector +
  pdb.bm25 + RRF 的对照（PLAN 1d）。**2026-10-19 实测基线**（PG 那套在本机跑不起来，
  于是这份 fixture 就是"将来对照的基准"）：14 个节点 × 14 条查询，precision@1
  0.929、precision@3 1.000、真实命中最低分 0.637（地板 0.35）、离题查询什么都不落地。
  也就是说地板没有切掉真命中——这正是那个常数存在的意义：被校验。
- `embedding` 节点在 2026-10-17 改成了**本地**：`base-url` / `endpoint` /
  `api-key-env` / `timeout-ms` 去掉，`model-dir` 命名工件目录（`config.json` /
  `model.safetensors` / `tokenizer.json` 按固定名在目录里找），
  `KRYSTALLIZER_MODEL_DIR` 可覆盖它。工件本身住在本机、不进仓库——这是
  任何模型尺寸的东西的既定规则。**2026-10-21 以「模式」重开**：同一个 node 在
  `mode "remote"` 下重新接受 `base-url` / `model` / `api-key-env` / `timeout-ms`。
  只留本地形态时，「不借外部算力」是个没人说出口的仓库级假设，而绕开它的另一条路
  ——给有 GPU 的机器另做一套记忆后端——会打断本 ADR 唯一捆住的东西：向量空间属于
  记忆系统。为需要它的模式把删掉的字段请回来；本地模式的字段在那边被拒绝，于是
  只改了一半的文件不会跑起来。
