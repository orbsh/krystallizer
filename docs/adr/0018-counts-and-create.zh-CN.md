# 0018 — 计数发生在调用当时，技能由模型创建

> **语言：** [English](0018-counts-and-create.md)（主） · [中文](0018-counts-and-create.zh-CN.md)

**状态：** Accepted（2026-10-26）——同日落地：`touch_skill` 与 touch 门、recall
的计数改为尽力、gravity 的第五条工具 `create_skill`。
**日期：** 2026-10-26

## 背景

两处缺口，都是读代码读出来的，不是计划里写着的。

**没有任何东西在数技能。** 权重系统的计数器骑在**边**行上（ADR-0005），而 skill
是**节点**——所以 `invoke_skill` 什么痕迹都不留。「这个 skill 用过几次、还能不能
用」当时答不出来，而 ADR-0016 的提议队列只能靠 gravity 在 turn 末上报整段组合来喂，
永远不靠调用本身。

**计数站在了它不该站的位置上。** recall 在服务时顺手 `read_count + 1`，并且用 `?`
把错误传出去——计数写失败，整次读取失败。一个副产品在扣着答案当人质。

**技能能跑，但不能写。** `commit_memory` 是模型的动作：它在轮内判断某样东西值得留。
技能没有对等物——它只从人的 curl 或统计提议里来。同一类判断，记忆和技能却是两种东西。

## 裁决

**1. 一次调用两条记录，落在调用方真正知道点什么的两个时刻。**

派发时记 `attempt`（结果未知），答案回来时记 `success`。store 不推导任何东西：
`calls` 与 `ok` 是节点上的 prop，差值就是失败数。**先记尝试**是「试过且坏了」成为
可见状态的唯一办法——反过来（一条记录自带结果）只有返回了的调用才写得出来，而那正好
是不需要诊断的情形。

**2. 节点计数与边计数回答不同的问题。**

节点计数是使用遥测：这东西还活着吗、值不值得留、是不是被试过然后放弃了。边计数是关联
权重：这两样东西有多该在一起，那是排序的输入。互不替代，而两者都叫「计数」只是词汇的
巧合。

**3a. 2026-10-27 修订：计数是声明字段。** 它们原本是 props，理由是「一次到达一份的
应用遥测」。那个理由在访问模式上是错的，而在测量本身没错：每个调用都抬一次的数字是**热路径
上要读**的，动态段是一次 map 查找，而那次 touch 本来就要重写这一行。`invoke_calls` /
`invoke_ok` / `last_invoked` 现在是 `EntityRow` 上的字段，一次 touch 仍然是**一次**写
（`merge` 把命中声明字段的名字路由到行上，props 不动）。向量仍然留在行外（ADR-0019），
这与它不矛盾：每次调用都变的八字节和从不改变的 1.5–2 KB，是同一条规则的两端。这次挪动之所
以便宜，只因为 okm 的布局字节是戳记而不是兼容承诺（okm ADR-0042）——字段放在前面、读者会去
找的位置，号被重置了。

**3. 计数永不失败它所计的那件事。**

recall 的计数写不下时，照原样回答事实；touch 门的答案是回执，gravity 忽略它。计数器是
merged 进 dynamic segment 的 prop：不声明字段、不加新列、不重贴标签。但按 okm ADR-0035，
一次 bump 仍然是整文档写入——这正是向量必须离开这一行的原因（ADR-0019）：让一次计数不再
重编码一个它不可能改变的向量。

**4. 技能由模型创建，与记忆对称。**

`create_skill` 是第五条固定工具（gravity ADR-0004）：name（身份）、title、content，以及
三个步形部分。同名再声明即合并（ADR-0015）。别的路径都不创建技能——统计算出来的提议留在
原处，因为它覆盖的是模型**没注意到**的那部分，而且它仍然只能**提议**。

**5. 步形部分以 JSON 文本跨边界，转换发生在边界上。**

模型写的是数组；k10r 存的是 TEXT、且一个字节都不解析（ADR-0012 §2）。转换归调用方，因为
它拥有那条线——教 store 学会模型的习惯，就是给 store 添第二套 schema 的做法。

## 后果

- **语料可以从对话内部长出来。** 一轮里琢磨出来的做法，在那一轮结束之前就已经是 skill；
  没有任何东西在等批处理。
- **每个 skill 现在看得见两个数**（`calls`、`ok`）加最后一次的时钟。它们**不说明时间**：
  是总量，所以「热了一周」和「热了一个月」看起来一样。衰减是边形状的（ADR-0005），搬不
  过来。
- **一次计数是一次整文档写入。** 在向量搬出这一行之前（ADR-0019），它要连带重编码向量；
  搬走之后才真的是「一次小写入」。
- **计数器无界、从不修剪。** 在只有人或回顾阶段读它的时候，这可以接受；一旦有东西按它
  排序，就必须选一个半衰期，那也是它的代价第一次出现的时刻。
- **ADR-0016 的 turn 末上报，作为唯一写者已经冗余。** 调用现场的计数本身就带着重复信息，
  而模型可以直接创建。重切那份记录是下一步，不是这一步：计数存在之后，「提议到底是干什么
  的」是要重答的问题。
