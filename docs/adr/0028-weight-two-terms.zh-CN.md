# ADR-0028: 权重是两个项 —— 累计给的有上限底数，环给的当期项

**状态**：草稿（2026-11-12）。建立在 ADR-0005 尚未落地的修订之上（payload v4 的两个访问环、时间放查询期），不取代它。

## 背景

ADR-0005 定下的形状是本条推理的前提：计数器与两个环骑在边行上，存储的 `weight` 是计数器的单调函数，时间信息只在查询期用于重排 `recall` 已经取回的那批事实。这个形状带出三个问题，都是读者最先撞上的。

**1 纯当期性会丢掉"老而承重"的事实。** 一条几年前被大量访问、此后无人问津的事实，在查询期的当期项下会衰减到几乎为零，而它恰恰可能是某个问题唯一需要的。衰减回答的是"这条现在还热吗"，不是"这条是否成立/是否被确立"；后者由累计计数回答，而现在在查询期被整个丢掉了。

**2 象限阈值随年龄漂移。** 四象限用绝对计数切（`RARITY_READ_FLOOR`、`RARITY_WRITE_CEIL`）。计数只增不减，时间一长几乎所有事实都落在"高读"那一侧，矩阵退化成一条线。象限本来分的是**行为**（读重还是写重），那是速率，不是累计。

**3 `write_count` 混了三件事。** 独立再断言（另一条路径重新推导或再次观察到）是证据；模型重写（反思、合并、规范化）与重复导入不是——它们改的是表示或只是重复搬运。三者现在都让同一个计数 +1、都推同一个环，于是"被反复加工"看起来像"被反复确认"。

## 决定

**1 查询期权重是两项之和，不是一个被衰减的总数。** 存储值仍然就是 ADR-0005 定义的那个（单调、对索引友好、两次写入之间不会自行过期）；查询期算：

```text
effective = base + live                                    （milli 整数）

base = min( ln(1 + read_count + write_count + tool_count) × K_BASE , CAP )
live = ln(1 + reads_in_ring) × 1.0
     + ln(1 + writes_in_ring) × 0.5
     + ln(1 + tools_in_ring)  × 1.5

K_BASE = 0.25    CAP = 3.0 个公式单位（= 3000 milli）
```

`base` 是"曾经发生过的一切"的残留，`live` 是"现在正在发生的"。上限是这套设计的全部要点：一条既成立又陈旧的事实永远不会掉到零，也永远赢不过一条此刻正被读的事实。这两个常数是**业务常数**（历史值多少、当期值多少），不是分数标定——正是这个区别让它可接受，而"置信度打分"不可接受。

**2 象限按速率切，不按累计切。** `RARITY_READ_FLOOR` 与 `RARITY_WRITE_CEIL` 比较的对象是环自己的跨度内有多少次访问，而不是累计计数。一条事实的象限于是可以双向变化，这本就是行为分类该有的性质。

**3 只有独立再断言算一次写。** 调用点自己知道是三者中的哪一种；计数与环只在再断言时前进。重写与重复导入改的是内容或来源，权重不动。这是写路径上的一条规则，不是新列——不改 schema，不加第三个计数器。

**4 环之外的历史不可恢复，也不假装可恢复。** 每个方向只留最近八次访问，比它更老的一切只剩 `base` 这一个痕迹。因此"某条信念在某个过去时刻是什么状态"这类问题**不能**靠重排回答，它同样不由时间取景查询回答，因为这个模型没有时间取景：知识库立足当下。历史被保留下来是作为当下的材料——一条经验、一个来源、一个怀疑的理由——而不是一个可以穿越回去的世界。把这条写成边界就是决定本身；用一条衰减曲线去近似它会是撒谎。

**5 没有离线复核，冲突在使用处裁决。** 不设后台扫描陈旧事实的作业，也不设复核队列：一条不再被碰的事实只是不再累积 `live`，而陈旧需要的信号仅此一个。使用中产生的新知识，与既有的兼容就合并、共享热度；不兼容就由热度决定谁先浮上来。两者都被召回进同一个窗口时，各自带着分数到达，由读者判断。由此对读路径有两条义务：**冲突组**（同主体、同关系、不同客体）不能被 top-k 截断拆开，否则较旧的一侧永远到不了读者面前，也就无从判断；**分数必须以分量的形式到达**（确立度、当期热度、最近时间），而不是一个数——单一数字会诱导"高就是真"，而没有任何计数器在测量真。

## 后果

- `recall` 的重排从"衰减过的总数"变成 `base + live`：老而成器的事实仍然可召回，而热的事实仍然赢。
- 象限的读法多了一个窗口定义（环的跨度）；在环存在之前写入的行环为空，退回累计计数——与 ADR-0005 的解码规则一致。
- 写路径多一条有名字的规则：再断言计数，加工不计。任何上报写入的消费方必须自己分类。
- 不改存储、不加索引、不做全表作业：一切都从行上已有的字段算出来。

## 被否

- **只有当期项、没有底数。** 丢掉的正是那些花几年才确立的事实；高累计、近期无闻的那类事实变得不可召回。
- **只有累计、没有当期项。** 这就是当前的问题：年龄不会输，被推翻的事实继续赢。
- **把算出来的 `effective` 存起来。** 它会在两次写入之间过期，ADR-0005 否掉存储值带时间的理由与此相同。
- **为再断言加第三个计数器。** 调用点本来就知道自己在做什么；加一列只是把同一个判断搬进 schema，并让所有历史行变得含义不明。
- **按时间取景的查询（"T 时刻我们相信什么"）。** 它需要的是**内容历史**，不是访问历史：环与计数记录的是这条事实被碰过多少次，从不记录存储里当时放着什么。即便时间戳无限保存，重放它们回答的是"2022 年什么最热"，不是"那时相信什么"。知识库用现在时读；过去是挂在活事实上的证据（一条取代说明、一个首次见到的时间、一个来源），而不是一个可以进入的平行世界。
- **由模型给置信度分。** 不可标定、跨模型不稳定，且它无法分解成读者能审计的东西。计数 + 环 + 一条写规则都是可观测的。
