# PROMPTS — 两个提示词面

> **语言：** [English](PROMPTS.md)（主文档）· [中文](PROMPTS.zh-CN.md)

状态：**Declared**（草案；这里还没有任何一处接线）。提示词是调用方持有的文本；
k10r 不持 LLM（ADR-0007），所以下面两套都在调用方一侧跑，都不是 k10r 的资产。

两条彼此隔离的路径，绝不可混为一谈（本页整合的那份草案把它们混了）：

1. **实时路径**——模型的**主动记忆添加**：gravity 那份固定工具清单里的一个工
   具，在用户轮内调用（ADR-0008 Update 2026-10-16：事实来自主动添加，不来自压
   缩那一趟）。
2. **写侧那一趟**——胶囊生成器：它在一条事实落地之后跑，与 ADR-0010 的写时消
   解、分箱同属一趟后台。它**不是**压缩旁路——旁路只做压缩（ADR-0008 Update
   2026-10-16）。

下面的命名一律按已定的词汇。源草案自造的名字或字段，标成 **[不在设计里]**、就
地留着，而不是悄悄采纳——见 §4。

## 1. 实时路径：工具定义（gravity 那一侧）

追加到 agent 的 system prompt。它的存在是为了让「添加」成为一种反射，而不是会
话结束时的冲刷，同时挡住模型存废话。

```
# 记忆：主动添加

你背后有一台图记忆引擎，通过一个工具触达。对话中一旦出现关键原子事实、架构
决策与用户明确偏好，就在轮内调用记忆添加工具把它们保留下来。

## 添加什么
不要添加闲聊、填充语、试探性推理。只在用户明确说出下列内容时添加：
- 核心工程决策——框架、存储、协议、性能约束（"我们选 Rust + Fjall 做本地存
  储，避免写放大"）。
- 不可变的规则与公理——领域逻辑或格式约束。
- 长期用户偏好——明确的状态、身份、刚性的风格偏好。

## 形态
把陈述拆成主谓宾三元组，序列化为**定长 9 元组**（JSON 列表）：三个角色按
head / rel / tail 顺序排列，每个角色是 `[值, 类型, 属性]`，由调用方把这条元组
交给 `ingest(fact)`。
- head / tail——值 = 实体（短、snake_case：`galaxy_repo`、`fjall_engine`）；
  类型 = 实体类型标签（小写单 token）；属性 = 实体的属性。
- rel——值 = 关系或约束（大写 snake_case：`USES`、`IMPLEMENTED_IN`、
  `PREVENTS`）；类型 = 关系类型标签（小写单 token）；属性 = 关系的修饰
  （时间 / 条件 / 原因 / 强度）。
- 属性为空写 `{}`——定长，槽位不省略；类型词表开放。

## 例子
用户："Galaxy 仓要转向一个叫 k10r 的嵌入式 Rust 记忆核——网络图数据库对无状态
架构太重了。"
  ["galaxy_repo", "repository", {}, "PIVOTED_TO", "architecture", {"reason": "network_graph_too_heavy"}, "k10r_core", "system", {}]

用户："写代码时我爱喝冰美式，但咖啡里绝对不能有奶。"
  ["user", "person", {}, "PREFERS", "lifestyle", {"context": "while_coding"}, "iced_americano", "coffee", {}]
```

让这段提示词保持诚实的几条注记：

- **工具名属于记忆族，不是 `k10r.store()`** **[不在设计里]**。调用方的名字是
  `recall_memory` / `commit_memory`（gravity 的固定工具清单，每族一对
  (retrieve, act)）；k10r 内部的写门是 `ingest(fact)`（确定性、定长 9 元组）
  与 `store`（flat 记忆）。工具名永远不是 k10r 的函数名。
- **模型不打时钟。** `ts_ms`/`sub` 是调用方的（ADR-0008 §3）。事实若带日期，由
  调用方给——让模型"给当前 ISO 时间戳"，它会编一个 **[待裁决：事实的 `since`
  谁来盖]**。
- **`confidence` 按草案那样写不在设计里。** 设计的排序输入是权重系统
  （ADR-0005：读/写计数、`tool_invoke_count`、读写象限），加上**读侧**的 landing
  置信地板。由模型逐条声明置信度是一个提案；若采纳，它是行上的声明属性，不是
  键的一部分。
- **这里不说事实去哪。** flat 记忆还是图，由调用方的路由与写时 fusion
  （ADR-0004/0007）决定，不由模型决定。

## 2. 写侧那一趟：胶囊生成器

输入：ADR-0010 增量 LPA 产出的**一个**社区的原子事实切片（定长 9 元组列表）。
这套提示词在写侧后台那一趟跑，于事实写入之后——从不在对话关键路径上。

```
你是嵌入式记忆核写侧那一趟里的一个图整固步骤。

## 输入
一份原始、孤立的原子事实子图簇，定长 9 元组记法（每行一条）：由局部标签传播
选出的、紧密绑定的语义社区。

## 任务
读三元组、它们的属性与时间戳。不要发明、不要超出字面断言外推。只做两件事：
1. 标题——一个概念标题，最多 6 个词，为这个社区命名。
2. 胶囊——1–2 句高密度摘要，抓住因果、已定的选择或行为模式。它成为缓存锚点，
   让下游读取不必重新遍历整个社区。

## 输出
只输出原始 JSON——不套 markdown 围栏、不写前言、不写问候：

{"title": "string (max 6 words)", "summary": "string (1-2 sentences)"}

## 例子
<§4 样例里的元组切片>
-> {"title": "K10r Core Embedded Storage Selection", "summary": "The k10r core is an embedded Rust memory system using the Fjall KV engine to eliminate runtime write-amplification; the arroy vector-search dependency was dropped to keep execution local."}
```

胶囊住哪是 ADR-0010 的事（节点行上的 community id + 社区反向索引 + 胶囊）；
"Layer 3" **[不在设计里]** 是草案的编号，不是本设计的词汇（范式文档的分层是写
入层 / 组织层 / 检索层）。
